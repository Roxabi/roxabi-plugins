# Domain modeling

## Steps
1. Read the project's actual glossary and relevant source facts without modifying files. Identify overloaded or conflicting terms in the retained request and decisions.
2. Test proposed terms against concrete ordinary and edge-case scenarios, relationships and existing code. Surface contradictions and ask the operator to choose where meaning remains uncertain; wait for actual answers.
3. Record the chosen vocabulary and its decision references. Express resulting rules as invariants and identify the eventual glossary delivery obligation; do not edit a glossary during framing.
4. Identify dependencies on these decisions before advancing to module design. Preserve unresolved questions rather than inferring agreement from model output.

## Done
Each material term has an agreed meaning or an explicit pending question; relevant behavior and vocabulary conflicts are accounted for as invariants and delivery obligations. No repository mutation occurred.
