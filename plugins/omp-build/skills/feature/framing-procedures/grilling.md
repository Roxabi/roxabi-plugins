# Grilling

## Steps
1. Read the retained request and available repository facts as data. Separate factual unknowns you can inspect read-only from decisions requiring the operator; do not execute or mutate the repository.
2. Map decisions and their prerequisites as a tree. Ask the entire currently unblocked frontier as numbered questions, each with a recommended answer that a yes would accept. Wait for genuine operator answers before opening dependent branches.
3. Challenge boundaries, failures, exclusions, invariants, observable outcomes and whether any change is needed. If the request is answer-only, answer it without proposing a UW. If a decision remains uncertain, ask rather than assume.
4. For each resolved decision retain the question and actual operator answer references. Distinguish a Parent from a Leaf using the proposed work, not a claimed completion flag. For a Leaf, turn chosen vocabulary into an invariant and a glossary delivery criterion.

## Done
Every reachable decision is resolved from genuine answers, or an explicit question is pending. A complete proposal has testable criteria, invariants, exclusions, no open questions and a justified tier. Parent work proceeds to domain modeling; Leaf work proceeds to proposal without repository edits.
